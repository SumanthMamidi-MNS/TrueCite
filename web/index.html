Known limitations

  • Local model substitution. Verification and generation run on a local Qwen 2.5 7B via Ollama, not the Claude API this was scoped for. Measured cost: a 5/11 false-refusal rate on answerable evaluation questions.
  • Follow-up resolution is best-effort. The last 3 turns are used to rewrite a follow-up (e.g. “what about for Unani?”) into a standalone question before retrieval — shown as an “Understand follow-up” step. The rewrite itself isn't verified the way answers are, so if it misreads what you meant, rephrase the question fully rather than continuing to build on it.
  • Statutory vocabulary gap. Terse clauses (e.g. Patents Act §3(p), which never uses the word “patent”) rank poorly against natural-language questions, so an answer may come from a secondary source explaining the same rule.
  • English-only corpus. Hindi retrieval is unverified — no Hindi source documents yet.
  • Not production-scale. Single user, local only.

Unanswerable questions: 5/5 correctly refused, 0 false answers.
